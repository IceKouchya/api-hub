# 005：备份、恢复演练与版本回滚

- **状态：** `ready-for-agent`
- **依赖：** 004 局域网、调用和故障切换验证完成
- **后续解锁：** 日常维护与后续升级
- **执行角色：** 独立运维窗口；敏感备份位置和密码由修本人控制

## 目标

建立 API Hub 的最小可验证恢复能力：记录当前固定 New API 版本、持久化位置、脱敏配置清单、备份位置、恢复步骤与升级回滚流程；完成至少一次不暴露密钥的恢复演练。

## 开始前必读

1. [Overview.md](../Overview.md)
2. [Plan.md](../Plan.md)
3. [Notes.md](../Notes.md)
4. [ADR-0001-new-api-selection.md](../ADR-0001-new-api-selection.md)
5. 001 至 004 的完成报告。
6. 当前固定版本的 New API 官方升级、备份和安全资料。

## 允许修改范围

- `D:\Agent-Codex\projects\api-hub\` 内的受控数据、日志、备份目录、项目 README 与运行维护记录。
- New API 专属 Docker 容器的停止、启动、重建和明确版本回退。
- 本项目 Vault 中不含敏感内容的备份清单、恢复证据和票据状态。

## 禁止修改范围

- 不删除唯一数据副本，不在未确认备份成功前清理原数据。
- 不将完整数据库、配置导出、API Key、Token、管理员密码、认证 Cookie 或原始日志放入 Vault、Git、Canvas、聊天或不受控云盘。
- 不升级到 `latest`，不跨越未审查版本，不在没有回滚点时升级。
- 不修改 Workbench、其他项目、全局 Docker 设置或无关容器。

## 备份对象

每次升级、重大渠道变更或定期维护前，至少保留：

1. 当前 New API 镜像版本和镜像摘要或等效可定位标识。
2. 当前容器名称、端口映射、挂载路径和启动方式的脱敏记录。
3. `/data` 持久化目录的一致性备份。
4. 必要日志的有限保留，用于诊断但不得收集不必要的敏感请求内容。
5. 渠道代号、统一模型名、主备关系和验证结果的脱敏清单。
6. 恢复前后已启用能力矩阵的回归结果，包括文本、流式、工具、视觉、推理和独立 Embedding 端点中实际启用的项目。

## 实施步骤

1. 确认当前服务已经通过 004 的功能验证；若当前服务本身不稳定，不应以它为恢复基线。
2. 记录固定镜像版本/摘要、容器状态、端口和挂载路径；不导出秘密环境变量。
3. 在 API Hub 项目目录下创建受控备份位置，确保其被 `.gitignore` 排除，并验证磁盘空间与访问权限。
4. 按目标版本的数据库一致性要求进行备份。若需要短暂停止容器以保证 SQLite 一致性，先记录计划并只停止 API Hub 容器。
5. 生成备份完整性证据，例如文件清单、大小、时间与校验摘要；不将数据库内容打印到终端或文档。
6. 在不覆盖唯一生产数据的前提下开展恢复演练：
   - 保留原数据目录及其备份。
   - 使用隔离的演练目录或明确的恢复副本。
   - 按固定版本启动恢复实例或恢复原实例。
   - 完成后台访问、`chat-general` 最小调用和持久化检查。
7. 将恢复结果、耗时、发现的问题和实际恢复命令位置记录为脱敏维护说明。
8. 为以后升级写明顺序：备份 -> 记录当前版本 -> 审查目标版本和公告 -> 在可回滚条件下升级 -> 运行 004 的核心验证 -> 失败则恢复旧镜像和旧数据。

## 验收标准

1. 当前已验证的镜像版本和持久化目录位置可定位。
2. 已有不被 Git 跟踪的持久化备份，且备份完整性已检查。
3. 已在隔离或受控条件下完成至少一次恢复演练。
4. 恢复后后台可访问，`chat-general` 最小调用成功，持久化配置存在，并对恢复前已启用的能力执行回归验证。
5. 回滚步骤能明确恢复到前一已验证镜像和数据，而不是“出问题再想办法”。
6. 文档中没有数据库内容、上游 API Key、New API Token、管理员密码或完整敏感日志。

## 日常升级规则

1. 不自动跟随 `latest`。
2. 每次目标版本先查 release notes 和 Security Advisories。
3. 先备份，再升级；先在最小路径验证，再恢复日常调用。
4. 遇到未预期错误、渠道异常、持久化问题或安全疑点，停止升级并回滚。
5. 升级完成后更新版本记录、验证日期、已知问题和下一次复审条件。

## 失败处理与回滚

- 备份失败：停止后续操作，保留现有服务，不删除或迁移数据。
- 恢复失败：保留原始数据和备份副本；恢复到此前仍正常运行的镜像和数据，记录失败类别。
- 升级后故障：停止新容器，使用记录的旧镜像版本与旧数据恢复；完成最小调用验证后再报告。
- 发现备份包含意外敏感传播：立即收紧访问、轮换受影响凭据并建立新的受控备份；报告只描述处置动作。

## 完成报告

报告包含：当前固定版本、备份时间、备份位置类别、完整性检查、恢复演练结论、最小调用结果、回滚路径和遗留风险。不得包含敏感数据、凭据值或完整备份内容。
