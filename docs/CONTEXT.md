# API Hub 领域词汇

本文件只定义稳定的业务术语；范围、实施步骤、运行配置和验收记录分别以 `Overview.md`、`Plan.md` 与 `tickets/` 为准。

## 核心术语

- **API Hub：** 本项目的个人局域网模型网关。它统一接收客户端请求、完成鉴权、选择渠道并返回兼容响应；它不是公开 API 平台、转售服务或多租户系统。
- **网关：** 本阶段由 New API 承担的运行实例，对内保存渠道、模型映射、Token 与必要日志，对外提供统一 OpenAI 兼容入口。
- **客户端：** 修本人控制的电脑、手机或平板上的调用程序、IDE、脚本或应用。客户端只使用统一入口和 New API Token，不持有上游 API Key。
- **统一入口：** 网关对客户端开放的 OpenAI 兼容 `/v1` 基础地址。第一阶段只通过 Windows 主机的局域网 IP 访问，不暴露到公网。
- **New API Token：** 网关签发给客户端的访问凭据，用于认证和权限控制；它与上游 API Key 不同，可单独撤销或按设备拆分。
- **上游 API Key：** 用户在已授权上游服务中获得的凭据，仅存放在 New API 的渠道配置中，不进入客户端、Git、文档、Canvas、日志或截图。
- **渠道：** New API 中连接一个上游服务的配置单元，包含服务类型、Base URL、上游认证、支持模型、模型映射、优先级、权重及必要参数覆盖。
- **主渠道：** 对某一统一模型名拥有最高可选优先级的渠道，正常请求优先发送至此。
- **备用渠道：** 当主渠道发生被策略认定为可重试的故障时，可接替请求的已验证渠道；它必须能提供等价或明确兼容的能力。
- **能力矩阵：** 对每个“渠道 + 真实模型 ID + 协议路径”记录文本对话、流式、工具调用、流式工具调用、视觉输入、推理控制、Embedding 与原生协议的实际验证状态。它是第一阶段实施项，不是未来功能清单。
- **能力契约：** 某个公开路由向客户端承诺的请求格式、端点、响应语义、流式行为、工具 schema、图像限制、推理控制与向量空间组合。主渠道和备用渠道只有能力契约兼容时才能互相接管。
- **统一模型名：** 客户端在请求 `model` 字段中使用的稳定别名，如 `chat-general`；它描述能力，不绑定供应商或上游真实模型 ID。
- **真实模型 ID：** 上游服务实际要求的模型名。渠道通过模型映射将统一模型名转换为该 ID。
- **模型映射：** 统一模型名到某个渠道真实模型 ID 的关系。不同渠道可以将同一统一模型名映射到不同的真实模型 ID。
- **路由：** 网关依据统一模型名、渠道可用性、优先级与权重选择具体渠道的过程。
- **可重试故障：** 由网络超时、暂时不可用、限流或部分上游 `5xx` 导致且策略允许切换渠道或重试的失败。`400`、`401`、`403`、模型不存在和参数不兼容不属于可重试故障。
- **流式响应：** 上游与网关持续输出片段的响应方式。已经向客户端输出内容后，不自动把完整请求重放到备用渠道，以避免重复执行或重复计费。
- **持久化数据：** 运行实例在挂载 `/data` 中保留的数据库和配置数据。第一阶段使用 SQLite 单容器，容器重建前必须保持该目录可恢复。
- **备份：** 对持久化数据、固定镜像版本、配置变更记录与恢复步骤的可验证保留；备份属于敏感资料，不得公开传播。
- **回滚：** 升级、配置或数据迁移失败后，使用先前已验证的镜像版本和备份恢复到可用基线的操作。
- **局域网：** 与 Windows 主机处于受信任私有网络内的设备范围。它不包括公网、端口转发、访客网络或未知设备。

## 能力别名约定

- `chat-general`：稳定的通用文本对话能力。
- `chat-fast`：优先低延迟或低成本的文本对话能力。
- `reasoning`：面向推理任务的模型能力。
- `vision`：支持图像输入的模型能力。
- `embedding`：通过独立 `/v1/embeddings` 接口提供的向量化能力；它不是聊天模型的附属参数，必须记录模型、维度、编码格式与向量空间。

工具调用、视觉输入、推理控制、流式输出与 Embedding 都在第一阶段能力矩阵中逐项实施和验证。未通过验证的能力不得对客户端宣称可用；能力不等价时不得为了“看起来统一”强行共用同一别名。
